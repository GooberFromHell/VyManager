# VyManager — Design Context

> Persistent design context for Impeccable and all design-aware tools.
> Source of truth for visual direction, principles, and constraints.

---

## Design Context

### Users
Mixed audience ranging from homelabbers running VyOS in personal environments to enterprise network engineers managing production infrastructure. Users are typically technical — comfortable with networking concepts (BGP, OSPF, firewall rules, NAT) — and need an interface that respects their expertise without getting in the way. Context of use varies: quick config checks, extended configuration sessions, and real-time monitoring during incidents. The interface must serve both the homelabber doing basic setup and the enterprise engineer fine-tuning BGP communities.

### Brand Personality
**Bold, confident, modern.** VyManager should feel like a capable tool that matches the seriousness of network infrastructure management while still feeling fresh and contemporary. It conveys competence and trust — users are configuring production routers through this interface. The tone is professional but not sterile; authoritative but approachable.

### Aesthetic Direction
- **Visual tone**: Strong, modern, data-rich. Dark mode primary (with light and "Interstellar" themes).
- **References**: Tailscale and Cloudflare (balancing simplicity with power, clean modern infrastructure tools), Grafana and Datadog (dense data-rich monitoring dashboards with polished dark themes).
- **Anti-references**: Overly playful consumer apps, cluttered legacy network tools with 2000s-era UIs, generic corporate dashboards that prioritize aesthetics over function.
- **Foundation**: shadcn/ui (radix-mira style), OKLCH color palette (neutral base, vibrant cyan primary), Geist Sans + Geist Mono fonts, Lucide icons, glass morphism on auth pages, card-based layouts with drag-and-drop dashboard.

### Design Principles
1. **Clarity over decoration** — Every element should serve the user's task. Prefer clear hierarchy and readable data over ornamental design. Network configs are complex enough without visual noise.
2. **Density when it matters** — Monitoring dashboards and config tables should pack information efficiently (Grafana-style), while setup flows and forms should breathe (Tailscale-style). Match density to the task.
3. **Confident interactions** — Bold primary actions, clear destructive states, obvious feedback. Users are making changes to live infrastructure — the UI should make the impact of actions unmistakable.
4. **Technical credibility** — Use precise terminology, monospace for values/IPs/commands, and structured layouts that mirror how network engineers think about their configs. Don't dumb it down.
5. **Progressive disclosure** — Show the essentials first, reveal advanced options on demand. Serve both the homelabber doing basic setup and the enterprise engineer fine-tuning BGP communities.

### Accessibility
- **Target**: WCAG AA compliance
- **Keyboard navigation**: All interactive elements must be keyboard-accessible with visible focus indicators (3px ring-ring/30)
- **Screen readers**: Semantic HTML, ARIA attributes on all interactive components (already enforced via Radix UI primitives)
- **Color**: Don't rely on color alone for meaning — pair status colors with icons and text labels
- **Motion**: Respect `prefers-reduced-motion` (tw-animate-css handles this automatically)
- **Contrast**: All text/background combinations must meet AA contrast ratios (4.5:1 normal text, 3:1 large text)

## Design System Reference

### Color Tokens (OKLCH, Dark Mode Default)
| Token | Value | Usage |
|-------|-------|-------|
| `--background` | `oklch(0.145 0.007 190)` | Page background |
| `--foreground` | `oklch(0.985 0.005 190)` | Primary text |
| `--card` | `oklch(0.205 0.007 190)` | Card surfaces |
| `--primary` | `oklch(0.6 0.15 190)` | Actions, focus, brand accent (vibrant cyan) |
| `--secondary` | `oklch(0.269 0.007 190)` | Hover states, subtle backgrounds |
| `--muted` | `oklch(0.269 0.007 190)` | Disabled backgrounds |
| `--muted-foreground` | `oklch(0.708 0.01 190)` | Secondary text, placeholders |
| `--destructive` | `oklch(0.704 0.191 22.216)` | Delete, error, danger |
| `--border` | `oklch(1 0.005 190 / 10%)` | Subtle borders (10% opacity) |
| `--input` | `oklch(1 0.005 190 / 15%)` | Form input backgrounds |
| `--ring` | `oklch(0.6 0.15 190)` | Focus rings (matches primary) |
